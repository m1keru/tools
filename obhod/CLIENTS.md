# Настройка и проверка клиента

Инструкция для того, кто получил от администратора папку с файлами и хочет
подключиться с компьютера или телефона. В примерах узлы названы `ru1` и `nl1`;
у вас имена будут свои, они видны в названиях файлов.

## Что лежит в папке

| Файл | Для чего |
|---|---|
| `xray/auto.json` | Компьютер. Сам выбирает рабочий узел и уходит с того, что перестал отвечать. |
| `xray/mobile.json` | Телефон на Android. То же самое, но для приложения. |
| `proxy.txt` | Адрес, порт и пароль прокси на компьютере. Первая строка для SOCKS5, вторая для HTTP. |
| `xray/<узел>-<транспорт>.json` | Компьютер, один закреплённый узел. Нужны для проверки по одному. |
| `links.txt`, `sub.txt` | Ссылки для ручного импорта в приложение. Запасной путь. |

В файлах ваш личный ключ. Не пересылайте их через российские мессенджеры и
почту и никому не передавайте: по ключу видно, что это вы.

## Компьютер

1. Скачайте Xray-core версии, которую назвал администратор, со страницы
   выпусков проекта `XTLS/Xray-core` на GitHub: архив под вашу систему
   (`Xray-windows-64.zip`, `Xray-macos-arm64-v8a.zip`, `Xray-linux-64.zip`).
   Распакуйте целиком: файлы `geoip.dat` и `geosite.dat` должны остаться
   рядом с программой.
2. Запустите в терминале из папки с Xray и не закрывайте окно:

   ```sh
   ./xray run -c /путь/к/папке/xray/auto.json
   ```

   В Windows: `.\xray.exe run -c C:\путь\к\папке\xray\auto.json`. На macOS
   при первом запуске система может отказать; тогда выполните
   `xattr -d com.apple.quarantine xray` и запустите снова.
3. Настройте браузер. Лучше всего Firefox, потому что прокси у него задаётся
   в собственных настройках, а не в системных: Настройки → Параметры сети →
   Ручная настройка прокси. В поле «HTTP-прокси» впишите `127.0.0.1` и порт
   из второй строки `proxy.txt`, отметьте «Использовать этот прокси и для
   HTTPS». При первом запросе браузер спросит имя и пароль: они в той же
   строке, между `//` и `@`, через двоеточие.
4. Системный прокси не включайте. Иначе в туннель пойдут все программы, и
   любая из них сможет узнать адрес, с которого вы выходите.

### Проверка на компьютере

Подставьте вторую строку из `proxy.txt` вместо `ПРОКСИ`:

```sh
curl -x "ПРОКСИ" https://api.ipify.org
curl -x "ПРОКСИ" -o /dev/null -w '%{speed_download} байт/с\n' 'https://speed.cloudflare.com/__down?bytes=20000000'
```

| Что проверить | Что должно быть |
|---|---|
| Первая команда | Адрес не ваш: это адрес выходного узла. |
| Вторая команда | 20 МБ скачиваются до конца, без остановки посередине. |
| Сайт, который у вас не открывался, в Firefox | Открывается. |
| Российский сайт, показывающий ваш адрес | Видит ваш обычный адрес: российское идёт мимо туннеля. |

Чего ждать:

- в первые 20–60 секунд после запуска запросы могут не проходить: программа
  ещё проверяет узлы;
- если узел перестал отвечать, программа сама уйдёт на другой за одну-две
  минуты. Ничего нажимать не нужно.

## Телефон на Android

1. Установите v2rayNG со страницы выпусков проекта `2dust/v2rayNG` на GitHub.
2. Перенесите на телефон файл `xray/mobile.json`: по кабелю или другим
   способом, которому доверяете.
3. В v2rayNG нажмите «+» → Custom config → Import custom config from locally
   и выберите `mobile.json`. Выберите появившийся профиль и нажмите кнопку
   запуска. Телефон спросит разрешение на VPN.
4. В настройках включите Per-app proxy и отметьте только те приложения,
   которым нужен обход: браузер, мессенджер. Банки, Госуслуги и другие
   российские приложения оставьте неотмеченными: они будут работать как
   обычно и не увидят туннель.
5. Автотест и «пинг всех серверов» в приложении не включайте.

Этот способ проверен только на компьютере: на телефоне его ещё никто не
запускал. Если профиль не импортируется или не подключается, напишите
администратору, что именно показало приложение, и воспользуйтесь запасным
путём.

**Запасной путь.** Скопируйте содержимое `links.txt` и в v2rayNG выберите
«+» → Import config from clipboard. Появится по профилю на каждый узел и
транспорт. Выберите тот, что назвал администратор; обычно это профиль входа
с `xhttp` в имени. В настройках маршрутизации приложения включите правило,
которое пускает российские сайты напрямую, если оно там есть. С этим
способом приложение само узел не меняет: если профиль перестал работать,
выберите другой вручную.

### Проверка на телефоне

Откройте в браузере, который вы отметили в Per-app proxy:

| Что открыть | Что должно быть |
|---|---|
| `https://api.ipify.org` | Адрес не ваш. |
| Сайт, который у вас не открывался | Открывается. |
| Российский сайт, показывающий ваш адрес | Видит ваш обычный адрес. |

## Если не работает

- Подождите 130 секунд, ничего не трогая. Оператор может «заморозить»
  соединение на пару минут, и частые попытки это только продлевают.
- Не перезапускайте программу и не переключайте профили чаще раза в две
  минуты.
- На компьютере попробуйте закреплённые профили по одному: остановите Xray
  (Ctrl+C), запустите с другим файлом, например `xray/ru1-xhttp.json`, и
  повторите проверку. Одновременно два профиля не запускайте.

## Что сообщить администратору

Чем точнее описание, тем быстрее найдётся причина. По каждой попытке:

| Что | Пример |
|---|---|
| Сеть | домашний интернет такого-то оператора, город; или мобильный такого-то оператора |
| Устройство и файл | компьютер, `auto.json`; телефон, `mobile.json` |
| Что показала первая проверка | адрес выхода или ошибка, дословно |
| Скачались ли 20 МБ | да, с такой-то скоростью; или остановилось на такой-то секунде |
| Время | когда пробовали, с точностью до минуты |

Адрес выхода из первой проверки и свой обычный адрес целиком присылать не
нужно: достаточно сказать, совпали они или нет.

## Администратору: что выдать

```sh
./obhod user add ИМЯ      # отдельный пользователь: его можно отозвать
./obhod render            # затем переустановить все узлы, чтобы они его узнали
```

Передайте папку `out/clients/ИМЯ/` целиком и назовите версию Xray: она
записана в `obhod show`. Отзыв: `./obhod user rm ИМЯ`, `render`,
переустановка узлов.
